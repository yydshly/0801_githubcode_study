最终目标 不是复刻某个品牌，而是把可验证的设计纪律迁移到自己的产品。

METHOD / 研究方法

我们研究的不是“像不像”，
而是判断如何成立。

把视觉感觉拆成四个连续阶段。每个阶段都保留来源、边界和下一步可验证动作。

  1. 01 · OBSERVE 先记录可观察证据

    截图、颜色、字体、空间关系、组件状态和内容密度；不急着解释它为什么有效。

  2. 02 · INTERPRET 再读取结构化判断

    对照 Refero 的 DESIGN.md，检查它如何为颜色、字体、组件和布局赋予语义。

  3. 03 · REVIEW 用统一六维框架复核

    从构图、层级、字体、颜色、材质和交互判断哪些结论可信，哪些仍是推断。

  4. 04 · TRANSLATE 最后翻译成实现规则

    形成 Token、组件规则、Do / Don't 和可复制简报，再交给 Codex 或前端实现。

研究边界

Refero 的公开页面是样例库；它没有面向访客开放 URL 转换入口。本项目也不把其内部维护接口包装成公开能力。

SYNTHESIS / 跨案例结论

六个网站，
沉淀出四条
可迁移纪律。

真正值得复用的不是某个颜色或圆角，而是这些网站如何控制注意力、证明产品价值，并把视觉选择变成稳定规则。

01 · COLOR BUDGET 强调色是一种预算

Linear、Stripe、Wise 与 Mercury 都限制高饱和颜色的职责。颜色越少，主操作越明确。

实现提示：先定义强调色允许出现的组件清单。
02 · PRODUCT PROOF 主视觉必须证明价值

开发者工具展示真实产品界面，金融品牌展示信任场景；装饰不能替代产品证据。

实现提示：给每张 Hero 资产写清它要证明什么。
03 · DEPTH SYSTEM 深度来自表面阶梯

成熟暗色系统主要依靠明度、边界和内容密度分层，而不是给每张卡片添加阴影。

实现提示：先建立 canvas / surface / raised 三层表面。
04 · TYPE ROLES 字体角色比字体品牌重要

真正可迁移的是展示、正文、元数据三种角色的比例、字重和节奏，而不是商业字体文件。

实现提示：为每个角色定义职责，再选择可授权替代字体。

ANALYSIS MODEL / 分析模型

一份可用的设计分析，
必须分清三种信息。

层级回答的问题允许的内容风险
EVIDENCE
可观察证据 页面实际上呈现了什么？ 截图、数值、颜色、字体、排列、状态 只看单一视口会遗漏响应式行为
INTERPRETATION
设计解释 这些选择为什么形成当前气质？ 层级、节奏、品牌性格、组件角色 解释可能主观，不能冒充官方规范
TRANSLATION
实现翻译 新项目应该如何复用这种方法？ Token、组件规则、Do / Don't、验收标准 原样复制会带来品牌与版权问题
