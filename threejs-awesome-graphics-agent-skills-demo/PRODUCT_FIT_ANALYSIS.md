# Product Fit Analysis

## 我们现在有什么

`glass-worlds-gallery` 是一个沉浸式研究展厅：用户在持续的 Three.js 星场中浏览玻璃球，每个球体包裹一组研究/能力场景；点击后进入内容详情，底部还有本地 World Composer 入口。它的产品核心不是“做一个 3D 球”，而是用空间运动组织研究内容的发现路径。

## 技能包能增强什么

### 1. 玻璃球从视觉容器变成空间内容单元

现有产品已经有双层玻璃、Fresnel、纹理内球和局部视差。技能包里的材质和水体光学方法可以进一步把材质参数按原因组织起来：厚度、边缘高光、反射/折射、内部深度和纹理可读性一起调，而不是单独堆透明度或后处理。

产品意义：用户会更容易相信每个球体是一个“可进入的世界”，而不是一个缩略图。

### 2. Atmosphere 和 Content 变成两种镜头导演模式

现有产品已经有 `Atmosphere / Content` 切换。技能包的 camera direction 和 procedural animation 能把镜头、球体轨迹、停留时机、焦点交接写成明确的时序系统：氛围模式负责建立空间情绪，内容模式负责让 3–5 个主题世界稳定可读。

产品意义：同一套场景不需要用一套折中的参数同时满足品牌首页和研究导航。

### 3. 高光成为内容层级的一部分

现有玻璃和粒子效果很容易在场景图较亮时产生竞争。技能包的 image pipeline、exposure/color grading、bloom 规则可以让曝光、选择性发光和内容模式联动。

产品意义：研究主题、标题和 Enter world 操作不会被统一的发光效果抢走；产品仍然保留“玻璃世界”的识别度。

### 4. 视觉迭代从感觉变成证据

现有项目已经有丰富的验证记录。技能包进一步强调固定相机、可重复 seed、无后处理基线、debug 视图、近/中/远距离和画质档位。

产品意义：以后比较“更像品牌首页”还是“更适合研究展厅”时，可以比较同一组可回放证据，而不只是比较一张偶然截屏。

## 不应直接套用的部分

- 上游技能包不会替我们决定研究主题、信息架构或产品 CTA。
- 海洋、行星、云雾等技能只有在产品语义需要时才值得接入，不应因为技术上存在就把场景做满。
- 后端生成、AI 调用、账户、持久化和真实内容管理不在该包的职责范围。
- 上游示例代码/素材的许可证需要单独复核，不能默认全部可以直接并入商业产品。

## 建议的产品化路线

1. 保留现有 Glass Worlds 作为产品入口。
2. 先把 camera direction、procedural materials、image pipeline 和 visual validation 形成四个产品级可调模块。
3. 用这四个模块完成一次“Atmosphere -> Content -> Enter world”的完整镜头/内容交接。
4. 再根据具体研究主题决定是否引入 water optics、volumetric clouds 或 procedural VFX，而不是一次性加入全部技能。

## 页面中的体验化说明

为了让产品意义可以被直接体会，而不是只停留在文档里，demo 增加了三个互相衔接的入口：

- `看懂这套库`：解释技能包的身份、覆盖范围和正确使用顺序；
- `这个效果怎么做？`：解释当前效果的五层构成，以及每层为什么存在；
- `这套库对产品的意义`：把技能包翻译成 Glass Worlds 的产品收益，并提供 `进入产品演示` 与 `查看详细映射` 两个下一步。

这三个入口对应“库是什么 → 效果怎么成立 → 对我们的产品有什么用”的认知路径。它们被做成前景抽屉，场景仍保持可见，因此用户可以把说明和当前画面即时对照，而不是离开 demo 阅读一份孤立说明。
