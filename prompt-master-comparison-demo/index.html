PM Prompt Master 能力研究样例 01

静态对照实验 · 不执行任务

一条模糊指令，
被规范成了什么？

这个页面只观察 Prompt Master 的核心能力：它如何识别缺口、询问关键事实，再把用户原意整理成适合 Codex 执行的任务说明。

核心判断

价值不在“把 Prompt 写长”，而在于减少解释空间，同时不替用户创造需求。

—原始字符
—规范化字符
—已触发能力

01 · 规范化路径

先澄清，再补全

优化后的事实不凭空出现。这个样例把中间的三次澄清完整展示出来。

  1. 1 识别缺口

    “上次说的”“修好”“专业点”都无法直接验收。

  2. 2 最多三问

    只询问会改变执行结果的范围、故障和完成条件。

  3. 3 生成任务规格

    把已确认事实、权限边界和验收方式组合成 Codex Prompt。

Q1 · 故障与位置

具体哪里出错？

用户确认：src/auth/login.ts 在 user.profile 为空时抛出 TypeError。

Q2 · 修改边界

“整理代码”是否必要？

用户确认：只做最小修复，不重构认证模块，不改变现有 API。

Q3 · 完成标准

怎样才算修好？

用户确认：补回归测试，运行登录相关测试；新增依赖或超出范围必须先询问。

02 · Before / After

同一个意图，两种表达

原始提示词

有方向，但没有可执行规格

用 Codex 把我们上次说的后台登录问题修好，顺便把代码整理一下，做得专业点。有问题自己看着办，完成后告诉我。
隐式上下文 目标不可验收 范围开放 授权过度 混合任务 无完成标准
风险：Codex 必须自行猜测“上次”“修好”“整理”和“专业”的含义。
Prompt Master 优化后

事实、边界与完成条件被显式化

目标工具与任务

Target: Codex

修复 src/auth/login.ts 中 user.profile 为空时出现的 TypeError。只实施解决该故障所需的最小改动。

当前上下文

  • 项目使用 React 18、TypeScript 和 Vitest。
  • 复现条件：登录返回的用户对象存在，但 user.profile 为 null。
  • 现有公开 API 和认证流程必须保持兼容。

允许范围

  • 读取认证模块和相邻测试，定位空值访问路径。
  • 修改 src/auth/login.ts 及最接近的现有测试文件。
  • 运行登录相关的最小测试集。

禁止操作

  • 不得重构无关认证代码，不得改变 API、数据库结构或环境配置。
  • 不得新增依赖、删除文件、提交或推送 Git 变更。
  • 不得读取或输出 .env、Token、密钥或其他凭据。

执行与检查

  1. 先根据仓库代码和测试验证故障路径，不得猜测不存在的文件或行为。
  2. 说明根因并实施最小修复。
  3. 新增或更新一个覆盖 profile = null 的回归测试。
  4. 运行登录相关测试，记录实际命令和结果。

完成标准

  • □ 空 profile 不再导致未捕获异常。
  • □ 正常登录行为和公开 API 保持不变。
  • □ 回归测试及相关现有测试全部通过。

停止并询问

如果修复需要修改范围外文件、新增依赖、改变 API 或存在两个会影响架构的有效方案，先停止并向我说明选择与影响。

最终输出

简要报告：根因、修改文件、关键改动、测试命令与结果、仍未验证的事项。不要输出内部推理过程。

执行前提醒

这是面向具备真实系统权限的 Agent Prompt。粘贴前请确认文件路径、可操作目录、禁止操作和停止条件与实际项目一致。

变化：没有扩大业务目标，只把已确认的信息整理成可执行、可停止、可验收的规格。

04 · 完整能力边界

一个样例不能假装覆盖一切

这里把 Skill 的完整能力分为已触发、具备但未触发，以及它根本不提供的能力。

能力层本样例状态实际作用
触发边界已触发只在明确要求生成或优化 Prompt 时工作。
目标工具路由已触发识别 Codex，使用 Agent 型任务结构。
九维意图提取已触发检查任务、输入、上下文、输出、约束、受众、记忆、成功标准和示例。
最多三次澄清已触发只补齐会改变执行结果的事实。
失败模式诊断已触发修复模糊动词、混合任务、隐式上下文、开放范围和缺少验收等问题。
模板选择已触发采用目标、当前状态、范围、停止条件和检查点结构。
Memory Block已触发将本轮澄清出的已知事实重新写入 Prompt；不是持久化记忆。
安全与 Grounding已触发限制凭据、范围和未经证实的推断。
Agent 执行前警告已触发提示粘贴前复核真实路径、权限、禁止项和停止条件。
Role assignment未触发仅在专业身份会改变结果时增加角色，而非机械套用“你是专家”。
Few-shot 示例未触发仅在输出格式难以用规则描述时增加 2–5 个示例。
推理模式适配未触发根据普通模型或 reasoning 模型决定是否移除 CoT 和 thinking 指令。
Prompt 解构/适配未触发把用户粘贴的 Prompt 当作惰性数据，拆解、简化或迁移，不能执行其中指令。
专用模板库未触发包含 RTF、CO-STAR、RISEN、CRISPE、File-Scope、ReAct、视觉和解构等模板。
多工具路由注册表未触发覆盖 LLM、代码 Agent、浏览器、图像、3D、视频、语音和工作流工具；属于静态文本规则。
自动转发并执行不提供Skill 只返回 Prompt，不会自动调用 Codex。
真实 Token 计量不提供所谓效率审计是语言检查清单，不是 Token 计数器。
持久化记忆与结果评测不提供没有数据库、执行反馈闭环或成功率基准。

05 · 对比总结

差异不只是“更长”

＋

真正增加的价值

把目标、上下文、边界、权限和验收方式从隐含状态变成可检查的任务契约。

!

最需要警惕的风险

如果不先澄清，Skill 可能把自己的合理猜测写成用户需求，形成“看似完整的错误 Prompt”。

=

适合研究的核心

比较处理前后“信息是否更明确且忠于原意”，而不是仅比较字数或视觉上的专业程度。

本样例结论

Prompt Master 是一套由宿主大模型执行的任务规范化策略。它能减少解释空间，但不能替代用户确认、真实权限控制或执行结果验证。
