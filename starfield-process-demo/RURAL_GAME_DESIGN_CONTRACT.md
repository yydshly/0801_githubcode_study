# 可探索乡村游戏设计契约

## 修订 02：夜雨乡村调查

- **进入方式**：revision-led；用户以“继续”授权直接实现上一轮建议。
- **视觉目标**：Immersive / Spatial Stage。乡村 3D 场景持续作为操作空间，HUD 只解释任务、风险和反馈。
- **场景主题**：把原“乡村探索”升级为夜雨调查，不新增第七个展示案例。
- **主旅程**：从村口安全点出发，沿主路完成排水口、泵站和受阻道路三项调查，途中收集应急地图与备用电池，最后返回救援灯标完成任务。
- **布局约束**：所有移动、碰撞、危险区、任务、物资和出口继续位于同一水平 XZ 游戏平面；坡地只保留为不可改变导航的视觉背景。
- **系统分层**：关卡数据、视觉几何、碰撞、导航路线、危险区、任务区、物资区、恢复点和出口使用稳定 ID 分离管理。
- **局部照明约束**：调查点、救援灯标和玩家灯光必须附着可见发光体；禁用或隐藏发光体时同步关闭灯光。
- **支持表面**：桌面键盘和 390 × 844 触屏竖屏；保持现有深色视觉系统。
- **不在本轮范围**：敌人战斗、物理刚体、联网、角色骨骼动画、存档后台和真实 GIS 数据。

### 可观察完成标准

- 初始 HUD 明确显示当前调查目标、已完成调查、物资数量和暴雨风险；
- 玩家能沿清晰路线抵达三个调查点，危险积水会降低移动速度并给出可见反馈，但不会造成软锁；
- 两个物资只能收集一次，备用电池会改善玩家灯光或风险恢复；
- 三项调查完成后救援灯标改变状态，玩家返回并互动后进入完成状态；
- 重置恢复玩家、任务、物资、风险、天气与出口状态；
- 桌面与手机均可完成主旅程，房屋碰撞、地图边界、相机跟随和触屏按钮无回归；
- 页面无横向溢出，运行日志无新增 error / warn，生产构建通过。

## 本阶段目标

把应用展厅中的“乡村探索”从路线图升级为一个可直接体验的 Three.js 3D 游戏案例。用户进入乡村后，可以用键盘或触屏方向键移动，在同一张乡村地图上完成任务点、收集物品并抵达出口。

## 体验架构

- **空间形态**：Spatial Stage。3D 场景持续可见，说明、任务状态和移动控件叠加在前景层。
- **演示模式**：Technical Demo Film。通过“地形 → 路线 → 碰撞 → 任务 → 可玩关卡”的五个阶段解释能力是怎样叠加出来的。
- **场景底座**：复用乡村地形、道路、农田、房屋、树木、天气和光照。
- **游戏层**：增加平面玩家移动、简化碰撞体、任务节点、收集物、出口和重置状态。

## 主旅程

1. 从应用目录进入“乡村探索” live 案例。
2. 观察玩家、路线、任务节点和收集物在乡村空间中的位置。
3. 使用 WASD / 方向键，或移动端方向控件移动玩家。
4. 靠近任务点或收集物后按“互动”，完成任务并看到状态反馈。
5. 完成全部任务后抵达出口，看到“探索完成”；可以随时重置重新体验。

## 关卡约束

- 所有移动、碰撞、任务和收集都在同一个水平 XZ 平面上；地形高度只用于视觉贴地，不用于爬坡或垂直穿越。
- 碰撞数据与房屋等视觉装饰分离，使用稳定的关卡锚点和矩形碰撞体。
- 玩家出生点、任务点、收集物和出口都必须保持可见，并且拥有明确的重试路线。
- 场景局部光源必须附着在可见的灯、火炬或任务发光体上；本阶段不引入无来源的局部光。

## 验收标准

- 桌面端可以用键盘移动，移动端可以用方向控件移动。
- 玩家不会穿过关卡边界或已定义的房屋碰撞体。
- 任务点按顺序激活，互动后有可见反馈；收集物不会重复计数。
- 全部任务完成后出口状态改变，重置可以恢复初始状态。
- 相机平滑跟随玩家，玩家、当前任务点和可互动目标保持在可读范围内。
- 既有四个乡村 live 场景、聚焦模式、季节/天气控件不回归；园区孪生继续保留为 roadmap。

## 支持边界

本阶段使用程序化几何和自定义平面碰撞，不承诺真实物理刚体、角色动画、网络同步或真实园区数据。后续接入真实资产或物理引擎时，必须单独进行资产质量、碰撞比例和移动端性能验证。
