# 小区 / 园区数字孪生设计契约

## 本阶段目标

把应用展厅中的“园区孪生”从路线图升级为一个可操作的程序化空间原型。用户可以在同一张园区地图上查看建筑、道路、绿化和摄像头视角，并通过图层和天气切换理解它对物业管理、园区展示和空间导览的意义。

## 体验架构

- **空间形态**：Spatial Stage。园区 3D 场景持续可见，图层、天气和摄像头视角作为前景控制。
- **演示模式**：Technical Demo Film。按“场地 → 道路 → 建筑 → 绿化 / 摄像头 → 园区合成”展示能力如何叠加。
- **场景底座**：程序化园区地面、主路、广场、建筑体块、绿化带、水景和服务设施。
- **运行图层**：建筑、道路、绿化、摄像头路线、天气粒子；图层状态必须同时反映到场景和前景控件。

## 主旅程

1. 从应用目录进入“园区孪生” live 案例。
2. 通过五个阶段观察园区从场地底座逐步形成建筑、道路、绿化和运营图层。
3. 切换“全部 / 建筑 / 道路 / 绿化 / 摄像头”图层，观察空间内容如何变化。
4. 切换总览、园区入口和中庭摄像头视角，理解导览与巡检路线。
5. 切换晴天、阴天、暴雨和雾天，观察同一园区在不同运营环境下的可读性。

## 约束与边界

- 本阶段使用程序化几何，不声称代表某个真实园区；建筑体块和摄像头节点是可替换的原型资产。
- 摄像头视角使用稳定的预设路线，不接入真实视频流或外部摄像头 API。
- 图层互相独立，隐藏绿化或摄像头时不破坏建筑和道路的基础空间关系。
- WebGL 失败时仍保留应用说明、图层名称、视角名称和真实数据接入边界。

## 验收标准

- 园区孪生在目录中显示为 `LIVE`，并具有五个可切换的过程阶段。
- 场景中能辨认建筑、道路、绿化、水景和摄像头节点；不同图层切换有可见结果。
- 三个摄像头视角可切换，镜头移动平滑且不会遮挡主要场景信息。
- 天气切换能改变天空、雾、雨幕或地面湿润状态。
- 桌面端和 390 × 844 移动端没有横向溢出，移动端控件保持可达。
- 乡村四季、暴雨巡检、乡村探索、出行预演和夜间乡村故事不回归。

## 后续资产接入

真实园区平面图、建筑 GLB / glTF、道路 GIS、摄像头点位和巡检数据需要单独进行比例、接地、坐标转换、数据刷新和移动端性能验证。本阶段不把这些缺失数据伪装成已接入。
