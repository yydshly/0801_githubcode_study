# Starfield Process Design Contract

## 产品任务

让用户不仅看到漂亮的视觉效果，还能沿着可视化过程理解：背景、星点、闪烁、极光、星云、太阳光源、行星轨道、降雨、湿材质、程序化建筑、火星地形、探测车和最终合成分别由什么计算产生，并能直接对比五种场景。

当前工程分为两个页面：`/` 是技能原理实验室，`/applications.html` 是真实场景应用展厅。原理实验室不再继续堆叠应用案例；应用展厅负责把已有能力组合成乡村、园区、出行和游戏方向。

## Spatial Stage

- **主体**：星空和极光始终占据主舞台；
- **场景切换**：顶部选择器和主按钮在五个 WebGL 场景之间循环切换，画面、标题、过程步骤和指标同步变化；
- **过程控制**：右侧运行面板改变真实 Shader 阶段，而不是只改变文字；
- **解释层**：当前阶段同时显示标题、输入和 GPU operation；
- **自动演示**：按固定顺序逐步推进，用户也可以随时手动跳转；
- **状态**：`RUNTIME READY`、帧率、draw calls、星点网格和极光 ray steps 可见；
- **纯场景观察**：右上角 `FOCUS / 聚焦 3D` 可淡出解释层，保留 WebGL 舞台和场景切换，使空间层次、遮挡、雨幕深度与地表接触证据可以被直接检查；
- **移动端**：右侧面板变成底部可读面板，隐藏重复的底部浮层，避免遮挡；
- **回退**：WebGL 初始化失败时显示可读的错误说明。

## 过程到能力映射

| 过程阶段 | 上游能力 | 可见结果 |
| --- | --- | --- |
| 背景场 | sky/backdrop shader | 深空颜色和高度渐变 |
| 星点分布 | hash-based procedural starfield | 稳定、可复现的星点位置 |
| 闪烁运动 | time + seed + blink rate | 少量星点独立闪烁 |
| 极光体积 | raymarched aurora curtain | 噪声场形成的 HDR 极光 |
| 最终合成 | exposure / gamma / dithering | 可读的最终画面 |

## 深空星海过程映射

| 过程阶段 | 产品层实现 | 可见结果 |
| --- | --- | --- |
| 深空底色 | direction-based backdrop | 全屏深蓝黑空间，没有地平线暗区 |
| 远星层 | 粗方向网格 + hash | 铺满视野的稳定远星 |
| 近星闪烁 | 多尺度 hash + time pulse | 不同大小、颜色和速度的近星 |
| 星云带 | 多频 cloud noise + band falloff | 很弱的紫蓝色空间方向感 |
| 深空合成 | 复用上游 grade 路径 | 曝光、伽马、dithering 后的最终星海 |

## 太阳系过程映射

| 过程阶段 | 产品层实现 | 可见结果 |
| --- | --- | --- |
| 空间底板 | 深空 shader 背景 + 3D camera | 星空从“天空”变成可观察的空间舞台 |
| 太阳光源 | emissive sphere + PointLight + glow sprite | 太阳发光并照亮行星 |
| 行星轨道 | SphereGeometry + LineLoop + Saturn ring | 行星和轨道关系可读 |
| 轨道运动 | pivot rotation + self rotation | 不同速度和相位的公转、自转、月球和小行星带 |
| 太阳系合成 | background pass + Three.js scene pass | 可拖拽、可缩放的三维太阳系 |

太阳系的三维感知验收条件：默认镜头必须能同时看到球体受光面与暗面；至少有一条倾斜轨道投影为椭圆；前景行星、太阳和背景星点之间要有可辨认的遮挡与尺度差；拖拽和缩放后这些关系必须随相机变化，而不是只移动一张平面图。

## 暴雨城市过程映射

| 过程阶段 | 产品层实现 | 可见结果 |
| --- | --- | --- |
| 暴雨天空 | storm backdrop shader + fog | 深蓝灰云层、城市天际线和闪电前的天气氛围 |
| 城市体块 | InstancedMesh + seeded dimensions | 可复现的建筑高度、道路和窗光 |

## 火星探测过程映射

| 过程阶段 | 产品层实现 | 可见结果 |
| --- | --- | --- |
| 尘埃天空 | Mars backdrop shader + dust band | 红橙色大气远景和细小星点 |

## 新场景视觉验收约束

- **暴雨城市**：最终阶段必须能一眼读出雨幕、城市灯光和湿地反光；雨线分为远景细线与近景厚线，不能只依靠文字说明天气。
- **火星探测**：最终阶段必须同时保留火星球体、带纹理的地表和可识别的探测车；地表要有陨石坑或车辙等接触证据，不能只显示一块红色平面。
- **构图**：场景主体保持在左侧说明区与右侧过程面板之间的可见区域；面板可以遮挡背景，但不能遮挡唯一的主体证据。
- **材质**：暴雨使用冷色湿地/窗光，火星使用暖色尘土/行星表面；场景切换时 UI 辅助色同步变化，维持主题一致性。
- **观察模式**：聚焦模式只隐藏讲解层，不暂停场景、不替换几何；用户退出后应回到同一个过程阶段和相机状态。

## 当前边界

本案例用于理解程序化 VFX 和 Three.js 场景组合，不承诺真实天文星表、真实比例、物理大气散射、观测数据接入或生产级天文可视化。
