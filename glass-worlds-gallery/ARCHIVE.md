# Glass Worlds Gallery 阶段归档

归档日期：2026-08-04
归档状态：阶段研究完成，停止无边界视觉微调；后续只在出现明确产品场景时重新开启。

## 1. 归档结论

这个子项目已经证明：类似 Happy Oyster 首页的“星系中漂浮玻璃世界”呈现层，可以完全由 React、Three.js、WebGL、GLSL Shader 和本地图片完成，不需要世界模型、实时视频 API、专用 token、登录或后端。

当前实现适合作为：

- 沉浸式研究展厅；
- AI 能力地图或产品能力入口；
- 品牌首页的空间背景和内容导航原型；
- 实时视觉模型、世界模型或视频流的前端承载容器；
- 玻璃材质、图片球、GPU 粒子和连续飞行调度的实现样例。

当前实现不等于 Happy Oyster 的源码复刻，也不等于实时世界模型。它是依据公开页面观察、公开样式证据和本地运行验证完成的独立 WebGL 研究原型。

## 3. 当前实现能力地图

### 3.1 渲染栈

- React + Vite 负责页面、交互和构建。
- Three.js `WebGLRenderer` 提供持续全屏空间舞台。
- 自定义 GLSL Shader 负责图片球曲面采样、边缘折射、视角视差、色散、Fresnel 高光和圆形粒子。
- `MeshPhysicalMaterial` 提供外层 transmission、IOR、thickness、clearcoat 和环境反射。
- DOM 继续承载导航、详情、创建器、键盘入口和可读文本，WebGL 只负责空间与氛围。

### 3.2 场景资产

- 8 个语义世界，每个世界配置 3 张本地图片。
- 运行时同时保持 8 张活动场景图不重复。
- 归档版本使用 8 张专用 WebP 电影场景图，不在运行时调用图片模型。
- 图片、玻璃壳和球体几何复用，避免为相同资源重复创建 GPU 资源。

### 3.3 球体与玻璃

每个世界由四个共享几何层组成：

```text
图片纹理内球
→ 背面内层光学壳
→ 透明物理玻璃外壳
→ Additive Fresnel / 双方向动态高光
```

图片中心尽量保持清楚；折射、色散和视差主要集中在边缘。玻璃强度随远近逐渐增加，并通过每球独立高光种子避免所有球使用完全相同的反光方向。

### 3.4 运动系统

- 8 个球以统一生命周期错开运行。
- 4 个球使用固定物理尺寸的世界空间直线通道，覆盖 DL、UR、DR、UL 四个象限。
- 4 个球保留屏幕空间投影轨迹，作为同页对照组。
- 调度稳定保持 `2/2/2/2` 象限分布和 `0–1` 个近景球。
- 同象限轨迹通过角度与生命周期错位避免近景重叠。
- 球体完全越过对应屏幕边界后才回收到远处，不使用近摄像机透明消失。
- 鼠标控制轻微摄像机视差；滚轮同时临时加速球体和粒子。

### 3.5 粒子系统

- 共 1,790 个 GPU 点：1,450 个背景粒子 + 340 个前景粒子。
- 两层都使用固定 `1.18 CSS px` 尺寸，距离不通过点大小表达。
- 粒子均匀采样整个摄影机视锥，不向中间集中。
- 深度通过速度、亮度、透明度和视差表达。
- 远处渐入、接近摄像机前渐出，避免重置闪烁。
- 不使用方块粒子、中心粒子团或持续运动拖尾。

### 3.6 交互系统

- Explore / Directing 模式切换。
- 鼠标悬停球体时显示跟随标签并适度减速。
- 点击球体打开对应世界详情，并可切换 3 张场景图。
- 支持上一项、下一项、随机世界、关闭详情和 Escape 返回。
- “Create a new world”是本地模拟创建器，不调用模型、不消耗 token。
- 提供语义化世界按钮、可见键盘焦点和 DOM 可读内容。

## 4. 已验证的运行结论

- 生产构建通过，Sites worker 测试 4/4 通过。
- 研究展厅构建可以生成全部 5 个项目。
- 1280×720 页面无文档溢出，运行日志无应用警告或错误。
- 4 条物理通道在 112 个连续采样中完成每条 2–3 次回收，没有距离反向、半径回退或象限变化。
- 修复后可读球体的最小投影间距保持为正，近景球始终不超过 1 个。
- 物理通道在完全越过边界后回收，没有摄像机穿透、全屏放大闪烁或末段突然变轨。
- 粒子始终保持 `1.18/1.18` 固定尺寸；滚轮加速后会平滑恢复。
- 详情打开、关闭、悬停、点击、Escape 和焦点返回均通过浏览器检查。

当前构建仍有 Three.js 大入口包提示。它不影响研究样例运行，但如果进入正式产品，应按“生产优化”部分处理。

## 5. 两个关键对比结论

### 5.1 屏幕空间轨迹 vs 物理 3D 通道

| 项目 | 屏幕空间轨迹 | 物理 3D 通道 |
| --- | --- | --- |
| 位置 | 先计算屏幕坐标，再映射回 Three.js 深度 | 在世界空间中从远端点插值到近端点 |
| 大小 | 使用人为尺寸曲线 | 使用固定物理半径和透视投影 |
| 优点 | 容易导演构图、控制边缘裁切 | 距离、大小和摄像机视差关系更一致 |
| 当前视觉差异 | 与目标构图高度一致 | 因终点和投影尺寸被刻意校准，肉眼差异有限 |
| 当前结论 | 适合需要精确画面导演的球 | 提升了轨迹数学稳定性，但没有单独形成显著 3D 观感 |

归档版本保留 4+4 混合实现。只有在未来场景明确要求真实摄像机运动、强烈视差或空间交互时，才值得继续将全部球改成物理通道。

### 5.2 Happy Oyster 原版 vs 我们的实现

| 项目 | Happy Oyster 原版观察 | 我们的归档实现 |
| --- | --- | --- |
| 核心角色 | 球是可阅读、可进入的“世界卡片” | 球更多承担星系空间效果与研究入口 |
| 同帧可读内容 | 通常约 4–6 个球可以辨认内部主题 | 归档帧经常只有约 1–3 个球达到清晰可读尺寸 |
| 近景尺度 | 大球可达到约屏幕高度的 35%–55%，并大面积贴边裁切 | 更强调安全离场、稀疏布局和不重叠，近景相对克制 |
| 运动目的 | 发现世界 → 看清世界 → 从身边掠过 → 进入世界 | 建立星系氛围 → 展示玻璃、粒子和连续飞行机制 |
| 产品取向 | 内容优先 | 效果和实现研究优先 |

如果未来用于产品首页或世界入口，应优先提升球内内容可读性，而不是继续增加粒子或折射复杂度。

## 6. 按场景重新启用时的建议

### 6.1 研究展厅或能力地图

当前版本基本足够。按内容替换 8 个世界的图片、标题、说明和研究链接即可。重点保持 3–5 个可读中景球，不需要世界模型。

### 6.2 品牌首页或产品能力入口

优先调整球体尺寸与停留节奏：

- 较早进入 140–260px 的可读直径；
- 同帧保持 3–5 个可读球；
- 允许 1–2 个 320–500px 大球从四周贴边离场；
- 大球可以有 35%–55% 超出屏幕，但仍需完整离场后回收；
- 保持固定方向连续移动，不恢复“中心放到最大再突然转向”的旧问题。

### 6.3 球内循环视频展厅

将静态图片替换为 4–8 秒无缝循环视频纹理即可。需要额外处理视频解码、自动播放、暂停、纹理更新、带宽和弱设备降级，但仍不需要世界模型。

### 6.4 实时视觉模型或世界模型入口

玻璃球、粒子和调度仍由前端负责；只把球内纹理源替换为 WebRTC/WebSocket/视频流。此时才需要模型 API、鉴权、token/credits、延迟管理、并发限制、隐私和失败回退。

### 6.5 纯背景或活动页氛围

减少球体数量和交互层，保留稀疏粒子、玻璃高光和轻微视差即可。应降低 CPU/GPU 占用，并避免球体与主要文字、表单或 CTA 竞争。

## 7. 可选优化清单

以下项目不是当前归档缺陷，而是未来场景触发的可选工作。

### A. 内容可读性与构图（最高产品价值）

- 提前放大中景球，稳定保持 3–5 个可读世界。
- 提高近景最大尺度和边缘裁切比例。
- 为球体增加“远景发现 / 中景阅读 / 近景掠过”内容角色。
- 逐图校准主体位置、曝光、饱和度和折射强度。
- 避免 CTA、导航和大球主体互相遮挡。
- 悬停时保持可读，但近景阶段不能完全停住而破坏调度。

### B. 可感知的真实 3D

- 实现真正的 `screen-space / world-space` A/B 开关，并使用相同随机种子和时间轴。
- 让摄像机沿 Z 轴真正向前移动，而不是主要依靠球体向摄像机靠近。
- 将全部球、粒子和灯光放入统一世界坐标系。
- 使用图片深度图、前中后景分层或 parallax occlusion 增加球内空间。
- 使用全景图、cubemap 或视频环境替换普通正面图片时，重新设计内球采样。
- 增加摄像机横向移动时近球、远球和内部图层的差异视差。

### C. 玻璃材质

- 使用 HDRI 环境贴图强化真实反射。
- 通过离屏渲染或两阶段采样实现真正的场景折射。
- 把边缘厚度、色散和高光与球体朝向及环境光关联。
- 对不同内容独立配置 IOR、roughness、thickness 和 attenuation。
- 保持图片中心清楚，避免用强玻璃效果掩盖内容质量。

### D. 粒子与飞行感

- 保持固定粒子尺寸，只调整前后层速度、亮度、透明度和视差。
- 根据真实摄像机速度驱动粒子运动，而不是单独的视觉速度。
- 使用确定性种子便于录制和回归比较。
- 可以增加固定尺寸的柔和光晕层，但不要恢复方块、中心团或大面积拖尾。
- 按页面文字对比度动态降低局部粒子亮度。

### E. 球体轨迹与调度

- 将随机角度扰动改为可复现的 seeded scheduler。
- 根据内容重要性分配远、中、近角色，而不只按索引调度。
- 增加出生时的未来间距预测，继续避免运行中突然排斥或变轨。
- 如果增加球体数量，按投影半径而不是物理半径检查屏幕重叠。
- 保留完整边界离场、无摄像机穿透和无回收闪烁约束。

### F. 内容资产

- 使用统一焦距、主体位置和颜色风格的专用场景图。
- 为球体准备更适合圆形裁切的中心构图。
- 使用循环视频、360° 全景或带深度图的图片增强内部世界。
- 把图片生成作为离线资产流程时，运行演示不需要 token。
- 只有实时生成或实时响应用户输入时，才接入模型服务。

### G. 交互与产品化

- 点击球体后增加“进入世界”的镜头过渡，而不是直接弹出侧栏。
- 增加内容过滤、搜索、世界分组和深链接。
- 将本地创建器替换为真实 API 时，补充鉴权、上传、进度、失败重试和隐私说明。
- 增加暂停、自动巡游、录制或演示导演模式。
- 为球体提供可访问名称、键盘顺序和非 WebGL 内容列表。

### H. 生产与性能

- 懒加载 Three.js 场景，让 DOM 外壳先出现。
- 分析当前约 214KB gzip 的 JavaScript 入口并拆分可选交互。
- 增加纹理预加载、进度、错误占位和失败重试。
- 根据帧率动态调整 DPR、球体分段数、粒子数量和材质质量。
- 处理 `webglcontextlost`、弱 GPU、无 WebGL 和静态降级。
- 在支持媒体偏好模拟的环境中复测 reduced motion。
- 移动端不是当前优化重点；只有明确进入移动产品时再重新设计触控与构图。

### I. 研究与发布证据

- 使用真实 A/B 模式录制同一时间轴，而不是用查询参数命名版本。
- 保存一段原版参考录屏和一段本地同尺寸录屏，用于尺度、速度和离场曲线测量。
- 增加固定种子、固定视口、固定时间戳的视觉回归。
- 对正式发布补充 MP4、封面、字幕、发布说明和回滚提交。

## 8. 当前不建议继续做的事情

- 单纯继续增加粒子数量、亮度或中心聚集。
- 在没有 A/B 模式时继续把全部球机械改成物理通道。
- 在内容仍不可读时优先增加 bloom、景深、拖尾或复杂色散。
- 为静态首页效果直接接入世界模型。
- 为了追求完全复刻而复制原站业务内容、品牌资产或不可确认的内部算法。
- 在没有明确使用场景时继续调整大量常数。

## 9. 重新启动条件

出现以下任一情况时，可以重新开启该子项目：

1. 已确定它要用于品牌首页、研究展厅、能力地图或实时模型入口中的哪一种。
2. 已确定内容优先还是效果优先。
3. 已提供正式图片、视频、全景图或实时流资产。
4. 已定义目标视口、性能预算、同帧可读球数量和最大离场尺度。
5. 已决定是否需要真正的 A/B 模式、摄像机前进或球内深度。

重新启动时，第一步应先修改设计契约和验收指标，不应直接从继续调参数开始。
