# Research 08 · 四游戏视觉生产能力复现实验验证记录

> 日期：2026-08-06
> 契约：[`VISUAL_PRODUCTION_BENCHMARK_CONTRACT.md`](VISUAL_PRODUCTION_BENCHMARK_CONTRACT.md)

## 结论

R4 已把“机制可以运行”的四个 L1 实验提升为四个具有独立第一印象的微型游戏场景。提升来自真实运行媒体、统一视觉语法、场景密度、材质/灯光和界面包装，而不是把所有问题归因于3D模型。

## 浏览器证据

### Adventure

- 桌面第一帧可辨认海岸森林、立石、浅水、中央战斗路径、漂流者和潮木敌人；HUD不遮挡角色。
- 生成背景作为中远景，Canvas继续实时绘制角色位置、环境微光、攻击弧、粒子、闪白和震屏。
- 触摸方向键靠近敌人并攻击后，敌人生命 `100% → 82%`、连击 `0 → 1`，证明视觉升级没有替代状态系统。

### Online

- 世界背景、漂流者角色、装备槽和物品符号形成一个视觉系统，而不是孤立表格。
- 清除存档后选择“漂流斧”并装备，工具槽显示“漂流斧”，采集 `10 → 15`，本地保存反馈可见。
- 角色媒体承担身份表达；物品图标仍由程序化符号构成，边界清楚。

### Backroom

- 初始画面拥有连续拱架、机柜、96个实例化信号灯、地面导引线、重复顶灯、雾和扫描线。
- 运行统计由先前 21 calls 增至 25 calls；新增空间层次没有形成失控的逐物件绘制。
- 原有第一人称移动、A-01/A-02区域变化、氛围/结构模式仍可用。

### MiniTown

- 空地图已包含水面、沙岸、草地、道路环、44棵实例化树、26块实例化岩石和路灯，不再依赖建造后才像世界。
- 建筑增加主体、屋顶与独立窗灯；推进时间同时更新天空、水色、主光、路灯和建筑发光。
- 实际点击建造后建筑 `0 → 1`、人口 `0 → 4`，推进时间 `09:00 → 15:00`。

## 跨表面与降级

| 表面 | 结果 |
| --- | --- |
| 1280 × 720 | 四案例三栏工作台无横向溢出；Adventure、Online、Backroom、MiniTown均有清晰视觉焦点 |
| 390 × 720 | 无横向溢出；Adventure舞台、HUD、控制按钮完整；Online角色媒体保持可见 |
| `?visuals=off` | `data-visual-assets=fallback`；Canvas恢复程序化人物/场地，Online显示离线说明，交互与Three.js继续运行 |
| 默认增强 | `data-visual-assets=enhanced`、`data-three-status=ready` |
| 控制台 | 默认与资产降级路径均无错误和警告 |

## 性能观察

- 三项运行媒体合计约4.40 MiB，属于当前研究页面可接受的 A2 级组合负载；没有发布两个色键中间文件。
- 桌面和移动视口中案例切换、Canvas动画与Three.js镜头保持可响应；本轮没有发现用户可感知卡顿。
- 这不是正式性能剖析。进入大地图或增加动画图集时，需要纹理图集、WebP/AVIF评估、分案例懒加载和GPU帧时测量。

## 仍然成立的边界

- Adventure人物和敌人是静态透明媒体随状态移动，不是完整骨骼或逐帧动画集。
- Online没有独立高质量物品插画，也不证明多人服务器能力。
- Backroom仍为程序化 L2/L3 微场景，不等同原作94个GLB和完整声音/后处理资产。
- MiniTown有统一世界语法，但建筑种类、居民、交通和经济仍未进入验证范围。
- 因而本轮证明了“资产与视觉系统会显著改变成品感”，没有宣称达到四个原游戏的完整生产规模。
