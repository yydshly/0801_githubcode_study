先纠正一个概念

这不是“库”，是项目协作方式

网页提供的是提示词模板、职责划分和阶段验收流程。真正写游戏的仍然是 HTML、JavaScript、Three.js 或其他技术；Infinite Build 负责规定 Codex 应当如何长期推进、何时验证、何时继续以及何时停下来询问人。

CAPABILITY MAP

它到底提供什么能力？

把英文页面压缩成六种可以直接理解和验证的能力。

01

概念定向

先把创意变成统一镜头、画风、界面和玩法状态的概念方案，再决定是否开发。

产物：概念图 + 系统提案
02

最小可玩切片

不急着做大世界，只制作足以证明手感、核心动作、压力和回报的小型版本。

产物：5–10 分钟试玩版
03

体验反馈翻译

用户只需说“移动太飘”或“命中没感觉”，Codex负责定位最关键的不匹配。

产物：一个聚焦改进
04

长期目标

保存游戏承诺、审美边界、路线图和已验证版本，下次从当前成果继续。

产物：持续有效的目标
05

真实运行验证

不只看代码和测试，还要运行并实际操作最终画面，检查目标设备与输入方式。

产物：可复现证据
06

发布与继续

每个检查点通过后更新版本、日志和线上页面，然后选择下一个高价值问题。

产物：已验证发布版
THE LOOP

一次完整循环

长期并不等于一次做很多，而是让每个小步骤都能被看见、测试和追溯。

  1. PLAY

    试玩

    运行当前版本，按玩家影响排列问题。

    →
  2. CHOOSE

    选择

    只选一个最值得解决的问题，写清验收条件。

    →
  3. BUILD

    构建

    完成最小但完整的改进，不扩展无关系统。

    →
  4. VERIFY

    验证

    实际操作最终画面，确认有效且没有回归。

    →
  5. SHIP

    发布

    更新版本与日志，发布后再次检查。

    →
  6. REPEAT

    继续

    根据最新游戏表现选择下一个检查点。

    ↻
