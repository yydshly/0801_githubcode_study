# 《潮汐守望》候选概念 V1 复盘

状态：已生成候选概念，等待人工判断。尚未进入游戏编码。

## 本轮练习验证什么

不是验证 AI 能否画一张漂亮海岛图，而是验证它能否把同一个游戏承诺表达为三个连续状态：

1. 到达：风暴后的海湾、人物孤立、信号火熄灭；
2. 理解：退潮暴露路线，人物收集漂流木；
3. 回报：夜间信号火点燃，远船灯光回应。

生成资产：`assets/concepts/tidewatch-three-states-v1.png`

## 已经成立的部分

- 三幅画面保持了同一海湾、火台位置、人物比例、俯视镜头和 HUD 语言。
- “熄灭火台 → 搬运木材 → 点亮火台”形成了无需文字也能理解的状态变化。
- 冷蓝海面与暖橙火光形成明确回报，且视觉规模仍接近浏览器小型切片能够承担的范围。

## 暴露的问题

- 第二幅画面清楚表达了“得到木材”，但没有清楚表达“玩家读懂了潮线”。
- 海湾地形很有氛围，但具体的可走路线、危险水域和潮位变化仍不够系统化。
- HUD 已出现生命、饮水、饥饿和快捷栏暗示，这可能把首个切片错误扩张成完整生存系统。

## 反向理解

- 工作流贡献：先固定同一镜头和三个状态，使视觉偏差在编码前暴露。
- 图像能力贡献：快速给出一致的地形、人物、光照和 UI 语言候选。
- 尚未证明：人物控制、碰撞、潮汐模拟、拾取、资源交付和点火循环。
- 主动收缩：首个切片应移除饥饿与饮水，只保留时间/潮位压力和木材目标。

## 人工放行问题

进入 Stage 02 前必须明确回答：

1. 是否接受这一俯视距离、人物比例和低多边形画风？
2. 是否保留现有海湾形态与冷蓝/暖橙关系？
3. 第二状态是否必须重画，使“潮线路线”比“捡木材”更突出？
4. 是否同意删除 HUD 中的生命、饮水、饥饿暗示，只保留本轮核心信息？

只有这些问题得到确认，才开始编写首个可玩切片。
