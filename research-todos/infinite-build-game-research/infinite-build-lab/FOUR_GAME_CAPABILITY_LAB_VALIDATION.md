## 结论

四项实验均已形成“来源证据 → 本地复现 → 可观察状态 → 明确边界”的产品证据链。页面不是四个原作的复制品，而是四个独立能力的最小可运行验证器。

## 验证环境

- 生产构建页面：`http://127.0.0.1:4190/projects/infinite-build-lab/capability-lab.html`
- 桌面视口：1280 × 720
- 移动视口：390 × 720（页面内容宽度 375px）
- 渲染：Canvas 2D + 本地 Three.js ES Module / WebGL
- 输入：桌面按钮、键盘契约、触摸方向键与画布点击

## 四项运行证据

| 实验 | 实际操作 | 运行结果 | 结论 |
| --- | --- | --- | --- |
| Adventure | 使用触摸方向键靠近敌人并攻击 | 敌人生命 100% → 82%，连击 0 → 1；过近后敌人反击 | 移动、距离判定、攻击、生命、连击与画面反馈属于同一状态闭环 |
| Online | 选择“漂流斧”装备，再拆解“海螺碎片”并重新载入页面 | 工具槽为“漂流斧”，采集 10 → 15，材料 0 → 2，物品 6 → 5；重载后全部恢复 | 物品、装备、属性、拆解和本地持久化可以作为独立产品系统验证 |
| Backroom | 切换基础照明、氛围层、结构层，并使用触摸方向键前进 | 渲染保持 21 calls；区域 A-01 → A-02；雾、曝光、扫描线和线框结构可见切换 | 压迫感来自空间尺度、重复结构、光雾和观察方式的组合，而非单个模型 |
| MiniTown | 点击网格建造住宅，推进六小时 | 建筑 0 → 1，人口 0 → 4，时间 09:00 → 15:00；天空、主光与发光材质同步更新 | 数据状态能够直接投射为可见世界变化，构成建造模拟的最小闭环 |

## 验证过程中发现并修正的问题

1. 触摸方向键最初只在持续按住时移动，快速点按几乎没有反馈；现增加确定性步进，同时保留持续移动。
2. Backroom 初版氛围层过暗，技术运行但空间不可读；现提高材质层次、灯具自发光和近景照明，保留幽暗感但能辨认走廊结构。
3. 第一人称前进方向初版符号相反；现统一为朝镜头视线方向进入走廊。
4. Three.js 当前版本提示软阴影常量弃用；现改为受支持的 `PCFShadowMap`。

## 研究边界

- Adventure 使用程序化像素替身，不拥有原作图集与商业美术质量。
- Online 验证的是本地状态系统，不是多人在线、账号或服务器经济。
- Backroom 使用程序化 L1 模块，不等同于原作 94 个 GLB 资产和完整后处理链。
- MiniTown 验证建造状态映射，不包含居民 AI、交通和经济循环。
- 因此本轮可以决定“哪种能力值得迁移”，不能据此宣称已经复制四个完整游戏。

## R3.1：四游戏视觉实现路线总结

### 新增结论

- Adventure 与 Online 主要依靠 2D 媒体、角色图集、图标和界面承载人物与身份细节。
- Backroom 与 MiniTown 使用实时 3D，但通过模块化硬表面、固定等距镜头和风格化几何控制资产范围。
- 因此四个案例不能被概括成“都是 2D”；它们共同证明的是视觉目标与生产方式匹配比盲目追求自由写实 3D 更重要。
- 当前出生海滩与目标图片的差距主要来自生产模型、纹理、材质、动画与大气渲染，而不是继续增加装备或建造逻辑。
