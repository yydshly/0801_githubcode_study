# Research 08 流程研究页设计契约

> 请求修订：R2
> 日期：2026-08-06
> 页面：`workflow-practice.html`

## 目标锁定

- **进入方式**：在现有 Research 08 中新建独立研究页。
- **目标用户与场景**：没有游戏开发经验、希望先理解 The Infinite Build 方法再决定是否继续大型游戏项目的研究者。
- **第一印象**：这是一张有证据、有边界、能继续执行的研究地图，而不是概念宣传页。
- **视觉野心**：Editorial。
- **体验架构**：Editorial Flow。
- **主要旅程**：理解流程 → 对照四个真实案例 → 查看受控练习 → 检查真实产品证据 → 反向判断贡献 → 把每一步沉淀为可复用技能候选。
- **现有保留**：保留 `index.html` 的“雾中灯塔”旧样例，不把它伪装成本次严格复现实验。
- **不引入**：后端、登录、真实项目状态写入、自动调用 AI、3D 引擎或新的付费资产。
- **支持边界**：中文、暗色主题、现代桌面/平板/手机浏览器；页面在外部案例图片不可用时仍保持全部文字与操作能力。

## 用户阶段

1. 理解原网页描述的游戏开发流程。
2. 分析四个游戏的类型、参考角度、优点与局限。
3. 用一个受控样例映射全部开发阶段。
4. 通过“流程贡献 / 技术贡献 / 资产贡献 / 尚未证明”反向反思。
5. 为每个阶段记录问题、输入、动作、产物、证据、失败与技能候选，并按跨样例验证结果决定是否晋级正式 Skill。

## 信息与视觉方向

| 决策 | 选择 | 可观察约束 | 验收标准 |
| --- | --- | --- | --- |
| 首屏层级 | 先给研究结论，再进入流程和案例 | 首屏只有一个主标题、一个结论和两个主入口 | 不滚动即可理解“先复现方法，再讨论写实” |
| 内容顺序 | 结论 → 五阶段 → 四案例 → 样例驱动 → 反思 | 每一段回答一个研究问题 | 页面标题与导航顺序一致 |
| 案例呈现 | 概念/实机对照 + 可切换分析 | 不把截图当装饰；每张图有来源、标签和文字结论 | 四个案例均能显示类型、价值、优点、局限和迁移点 |
| 练习呈现 | 阶段控制台 | 阶段切换必须同步更新人类输入、Codex任务、产物、证据和反思 | 五个阶段键鼠可操作，当前阶段状态明确 |
| 颜色语义 | 暗蓝底、暖白正文、青色代表证据、橙色代表边界 | 不只依赖颜色传达选中状态 | 选中项同时有文字、边框或 `aria-selected` |
| 字体密度 | 中文正文优先可读，英文仅用于阶段标签 | 正文行宽不超过约 72 字符 | 桌面和 390px 手机无横向溢出 |
| 动效 | 只解释状态变化 | reduced-motion 下取消非必要过渡 | 切换内容不依赖动画才能理解 |

## 状态与操作约束

- 四案例切换是一个语义化 tab 系统，默认选择 `Phantasy Codex Adventure`。
- 五阶段练习切换是第二个独立 tab 系统，默认停在 `01 · 概念定向`。
- “复制第一阶段提示词”必须给出可见成功或失败反馈，不产生网络请求。
- 所有外链显式标注为外部游戏或原始来源，并使用新标签打开。
- JavaScript 不可用时，四个案例摘要和五阶段概览仍然在页面中可读。

## 自主权限与决策边界

- **已授权**：用户明确要求新建网页并用样例驱动练习，可直接完成布局、文案、交互、链接和验证。
- **需要用户决定**：只有当练习要从“流程页面”进入真实游戏编码、改变样例主题或重新启动大型《孤潮余生》生产时再询问。

## 可观察完成条件

1. 页面能从 Research 08 主入口进入，也能返回主入口。
2. 五个开发阶段均说明人、Codex、产物和验证证据分别是什么。
3. 四个游戏均有类型、参考角度、优点、局限和适合迁移的经验。
4. “潮汐守望”按真实状态标注已完成概念和首个可玩切片，Stage 03 等待玩家反馈。
5. 用户能切换案例、切换练习阶段并复制提示词。
6. 桌面、平板和 390px 手机无遮挡或横向溢出；关键旅程键盘可达。
7. 生产构建通过，浏览器无控制台错误。
8. Stage 01 和 Stage 02 均能回答“为什么做、怎么做、哪里失败、学到什么、能否复用”。
9. 页面明确区分学习记录、技能候选、跨样例验证和正式 Skill，不把一次成功包装成通用能力。
