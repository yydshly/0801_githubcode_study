# 项目蓝图网页设计契约

## 设计契约

- **进入方式**：基于已交付项目蓝图的 revision-led 内容与体验修订。
- **请求版本**：R3。
- **目标用户与情境**：没有游戏开发经验、需要先理解项目整体结构，再决定技术和制作投入的项目发起者。
- **第一印象**：这不是角色凭空出现在海滩上的生存关卡；玩家先经历一场有因果、有损失、有未解问题的客船海难，才独自抵达真实而陌生的小岛。
- **视觉目标**：Editorial；以四阶段概念图作为视觉锚点，以清晰的中文信息结构解释复杂系统。
- **体验架构**：Editorial Flow；从愿景、系统构建、系统呈现、现实抽象方法、南部海湾切片到开发路线依次阅读。
- **视觉限制**：深色自然纪录片气质；海水青、雨林绿、湿沙和火光作为语义色；不使用与游戏世界无关的通用后台面板风格。
- **信息限制**：首屏必须回答“做什么、为什么做、先做哪里”；正文必须明确区分世界运行层和世界表现层；新增内容必须给出“登船—风暴—失事—漂流—上岸”的连续因果，并解释为什么主角独自抵达、为何救援没有立即出现、为什么仍不能断言其他人全部遇难。
- **操作限制**：无需登录和后端；桌面与移动端均可阅读；系统卡片可点击查看“状态、规则、呈现、验收证据”；主要内容不依赖 JavaScript 才能理解。
- **状态限制**：支持系统卡片选中态、导航焦点态和无脚本基础阅读；只支持一套深色主题。
- **环境限制**：继续使用现有 Vite 项目；保留当前游戏入口和运行方式；不引入新依赖和大型渲染效果。
- **主要旅程**：打开项目蓝图 → 理解地区客货船如何在风暴中失事、主角为何漂到岛上 → 带着“是否还有幸存者、求救是否发出、自己漂了多远”三个问题进入陌生岛屿 → 看懂探索与风险规则 → 理解南部海湾切片 → 查看故事与设计文档。
- **用户阶段**：第一，网页形式构建整体描述；第二，Markdown 文档落地。
- **必要产物**：`overview.html`、独立样式与交互脚本、Markdown 文档索引及核心设计文档、构建与浏览器验证记录。
- **自主授权**：用户明确要求构建，允许在当前项目内完成可逆的页面、配置和文档修改。
- **用户决策边界**：购买商业资产、切换到 Unreal、引入后端、公开发布或扩大到完整岛屿不在本轮范围内；主角姓名、性别、职业、国籍和最终结局暂不锁定。

## 可观察完成标准

1. `http://127.0.0.1:4186/overview.html` 可直接打开，且当前 `/` 游戏入口仍可运行。
2. 首屏清楚说明项目愿景、核心命题和当前目标。
3. 页面完整覆盖世界运行层、表现层、现实抽象流程、七个核心系统、南部海湾切片和分阶段路线。
4. 系统卡片在键盘、鼠标和触屏下可选择，内容反馈清楚。
5. 桌面、平板和 390px 手机宽度下无关键遮挡或横向溢出。
6. `prefers-reduced-motion` 下非必要动画被关闭。
7. Markdown 文档有统一索引，内容与网页术语、范围和路线一致。
8. 生产构建成功，并包含游戏页和项目蓝图页。
9. 页面和文档明确区分“现实陌生感”与任意猎奇：岛屿宏观地理保持可信，变化来自天气、潮汐、生物、漂流物和事件条件。
10. 玩家情绪不是持续恐慌，而是休克、定向、谨慎探索、能力增长之间随安全与意外反复波动。
11. 每个重要发现至少包含可观察线索、可形成的假设、准备成本、可预判风险、结果和可保留知识。
12. 海难前情形成完整时间线，并解决现代大型邮轮会被快速定位的现实矛盾：使用偏远群岛地区客货船、受损通信、外海礁带、风暴洋流与偏离搜救走廊共同解释延迟救援。
13. 主角是“独自上岸”，不是开场就被叙事宣布为“唯一幸存者”；其他乘客、船员和求救信号成为后续探索问题。

## 信息与视觉方向

| 决策 | 方向 | 可观察限制 | 验收标准 |
| --- | --- | --- | --- |
| 首屏层级 | “世界不是背景，而是一套因果系统”为主标题，原型和文档为行动入口 | 首屏只保留一个核心命题与两个行动 | 5 秒内能回答项目是什么、下一步做什么 |
| 阅读结构 | 从抽象到具体，从世界系统落到南部海湾 | 每一节只回答一个核心问题 | 无需开发经验也能顺序理解 |
| 概念图 | 四阶段图作为世界目标，不冒充当前运行截图 | 图注必须明确“目标参考” | 不产生当前原型已达写实质量的误解 |
| 系统解释 | 每个系统都同时显示内部状态、规则、玩家感知和验收证据 | 不以技术名词替代解释 | 点击任一系统能理解其如何落地 |
| 响应式 | 桌面双栏、移动端单栏；导航可横向滚动 | 390px 不隐藏核心入口 | 无遮挡、无关键文字截断 |
| 动效 | 仅使用阅读进度、轻微入场和选中反馈 | 不承载必要信息 | reduced-motion 下仍完整可用 |
| 陌生体验 | “暂时无法读懂但可以逐步理解”的真实岛屿 | 不使用随机惊吓、魔法异常或无因果程序生成制造神秘 | 玩家能说明自己为何害怕、为何靠近、从结果中学会了什么 |
| 情绪节奏 | 休克与求生优先，安全稍稳后才释放好奇；意外会令情绪短暂回落 | 不把角色写成落地即砍树制作，也不让全程保持最高恐慌 | 首 20 分钟的行动、身体反馈和目标与真实漂流处境一致 |
| 生成边界 | 固定可信地理骨架，动态生成天气窗口、潮汐暴露、生物活动、漂流物与条件事件 | 生成结果必须能够由世界状态解释 | 相同地点在不同时段有新鲜变化，但仍能形成稳定知识 |
| 故事前情 | 偏远群岛地区客货船遇到快速增强的热带风暴，失去动力后撞击外海礁带；主角穿救生衣被洋流带离事故点 | 不使用现代大型豪华邮轮，也不依赖失忆或神秘力量掩盖定位与搜救问题 | 玩家能复述五个事件节点，并说出自己为何独自抵达、为何暂时没有救援 |
| 持续悬念 | 其他人是否幸存、求救是否完整发出、主角漂流距离未知 | 不在开场宣布全员死亡，不用任务日志提前给答案 | 三个问题分别连接海滩残骸、岛内踪迹、高地信号与后续救援系统 |
