# 10 · Unreal 写实画面与交互基准计划

> 状态：待执行 R1  
> 日期：2026-08-05  
> 暂定项目名：`castaway-island-unreal-benchmark`  
> 目的：用最小真实场景判断概念画面能否转化成稳定、可交互的游戏，而不是继续用静态截图推测。

## 唯一目标

建立一个玩家可以实际操作的南部海湾基准场景，同时验证：

- 地理构图是否可信；
- 人物是否具有真实尺度和基础动作质量；
- 地形碰撞、相机和涉水是否成立；
- 海水、岸线、天气和材质能否达到目标方向；
- 当前参考电脑是否能够稳定运行；
- 资产进入项目的流程能否被重复使用。

它不是完整游戏、不是第一章，也不是海难过场。

## 范围

### 可交互近景

约 50 × 50 米：

- 玩家苏醒点；
- 湿沙与潮线；
- 浅水涉水区；
- 三组可碰撞岩石；
- 一小片海岸植被；
- 一件可检查和拾取的沉船物；
- 一组通向内陆的陌生足迹。

### 视觉范围

约 150 × 150 米：

- 南部海湾弧线；
- 一侧岩岬；
- 椰林边缘；
- 内陆缓坡或山体轮廓；
- 远海、海平线、云层和天气前沿。

视觉范围不要求全部可到达，但不能使用一张平面概念图伪装成可进入世界。

## 唯一交互链

```text
玩家在沙滩获得控制
  → 行走并感受地形和镜头
  → 进入浅水，人物动作和声音发生变化
  → 发现一组陌生足迹
  → 集中观察并形成“有人或动物经过”的假设
  → 拾取一件沉船物
  → 远处云层聚集，风和海况增强
  → 玩家决定返回开阔海滩或靠近林缘
```

这条链只验证观察、行动、环境反馈和天气压力，不加入饥饿、制作、建造和复杂任务。

## 第一批资产

| 类别 | 数量边界 | 验收重点 |
| --- | ---: | --- |
| 正式人物 | 1 | 比例、骨架、动画、脚部接触、性能、许可 |
| 基础动作 | 6–8 | 待机、走、跑、转向、蹲下、拾取、涉水、受击或失衡候选 |
| 地形 | 1 块 | 海湾轮廓、坡度、岸线和独立碰撞 |
| 岩石组 | 3 | 不同尺度、接地、材质统一和简化碰撞 |
| 植被组 | 4 | 椰树、灌木、蕨类、海岸草；风动与实例化 |
| 漂流物 | 3 | 一件可交互，其余用于构图 |
| 海洋 | 1 套 | 远海、浅水、岸浪、泡沫和湿沙层次 |
| 天气 | 2 个状态 | 晴朗与风暴前沿连续过渡 |
| 声音 | 5 层以内 | 海浪、风、脚步、涉水、拾取反馈 |

所有资产先进入隔离检查场景，再进入海湾。检查内容包括来源、许可、比例、轴向、材质、纹理、碰撞、动画、LOD 和帧时间。

## 执行阶段

### B0 · 设备准备

动作：

1. 只读分析磁盘占用，提出可移动或可清理候选；
2. 用户确认后释放或增加至少约 150 GB SSD 空间；
3. 决定是否把内存升级到 32 GB；
4. 安装当前稳定版 Unreal Engine；
5. 建立版本、项目位置和缓存位置记录。

通过证据：编辑器可以稳定启动，项目、缓存和构建不会挤满系统盘。

### B1 · 空场景基线

动作：

- 创建空白第三人称项目；
- 固定 Windows PC、1080p 和目标画质；
- 创建测试地图、性能显示和固定镜头；
- 记录没有内容时的基准帧率和显存占用。

通过证据：同一入口可以重复进入场景并获得可比较数据。

### B2 · 人物、相机与碰撞

动作：

- 接入一名正式骨骼人物；
- 完成待机、走、跑、转向和蹲下；
- 建立第三人称相机、坡度和碰撞；
- 验证脚部接地和岩石阻挡。

通过证据：人物没有明显滑步、悬空、穿地或穿岩，镜头不会频繁进入模型和地形。

### B3 · 地理与海岸

动作：

- 构建海湾、岩岬、林缘和内陆轮廓；
- 接入岩石、湿沙和少量植被；
- 建立近景、中景和远景层次；
- 加入海面、浅水、泡沫和岸线过渡。

通过证据：固定镜头和玩家镜头都能读出海湾形态、水深变化和可探索方向。

### B4 · 涉水、互动与天气

动作：

- 加入浅水判定、涉水动作和声音；
- 加入足迹检查与漂流物拾取；
- 建立晴朗到风暴前沿的连续过渡；
- 让风、云、海况、植被和声音读取同一个环境状态。

通过证据：天气不是画面滤镜，而是多个表现模块对同一世界状态的同步反应。

### B5 · 质量与性能验收

动作：

- 在晴朗、风暴前沿和最重视角分别测量；
- 记录分辨率、画质档位、平均帧率、最低稳定表现和明显卡顿；
- 截取固定镜头和自由游玩录像；
- 汇总资产来源、失败方案和剩余风险。

通过证据：达到本计划的通过标准，或者形成明确的降级与停止决定。

## 通过标准

| 维度 | 底线 |
| --- | --- |
| 构图 | 玩家不看地图也能区分海湾、岩岬、林缘、内陆和远海 |
| 人物 | 正式人物比例可信，基础移动和脚部接触没有持续性破绽 |
| 碰撞 | 地面、岩石和浅水边界行为稳定，没有常见穿透和卡死 |
| 海洋 | 深水、浅水、岸浪、泡沫与湿沙至少有四层可读差异 |
| 天气 | 晴朗到风暴前沿连续变化，并同步影响云、光、风、海与声音 |
| 交互 | 足迹检查和漂流物拾取都能产生明确但不过度解释的反馈 |
| 性能 | 参考设备 1080p 最重状态稳定 30 FPS 以上，60 FPS 为优化目标 |
| 来源 | 每个外部运行资产都能追溯来源与许可 |
| 可复用 | 人物、资产检查、环境状态和性能入口可以服务下一块区域 |

## 不在本轮范围

- 完整客船和船体断裂；
- 完整开场电影；
- 整座岛屿；
- 饥饿、口渴、体温完整数值系统；
- 制作、建造和背包系统；
- 鱼、蟹、海鸟的完整生态；
- 攀爬、游泳、战斗和复杂动物 AI；
- 手机、主机和 4K 目标；
- 多人游戏和云存档。

## 支出阶段门

1. B0 前只允许硬件准备支出；
2. B1–B2 优先使用引擎内置内容、项目已有许可资产或免费候选；
3. 付费人物、动画、环境包或插件必须解决一个已复现问题；
4. 单项购买前记录价格、许可、替代方案和预期验收项；
5. B5 通过前总额暂不超过人民币 3,000 元；
6. 购买不能替代实机场景验证，未通过的资产不继续扩购同系列内容。

## 失败时怎么处理

- 人物质量不足：先更换人物或动画方案，不扩大地形；
- 海岸质量不足：缩小海湾，把预算集中到玩家可接触岸线；
- 性能不足：先降植被、阴影、反射和远景密度，再讨论硬件升级；
- 资产风格不统一：停止购买，建立材质和比例样板；
- 交互没有意义：修改线索和反馈，不增加更多物品；
- 基础场景仍无法成立：重新评估写实程度、目标平台或引擎路线。
