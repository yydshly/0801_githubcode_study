# 09 · 生产路线决策与阻塞评估

> 状态：生产决策 R1  
> 日期：2026-08-05  
> 目的：把概念、网页原型和最终游戏生产分开，明确当前能够继续什么、被什么阻塞、何时允许扩大投入。

## 当前结论

《孤潮余生》的产品目标已经形成：玩家作为海难幸存者，在可信但陌生的孤岛中，通过观察、判断、行动和承担后果，从恐慌求生逐渐走向理解环境和建立生活。

当前缺少的不是更多故事或系统设想，而是从目标画面到可运行游戏的生产链。现有网页版本证明了流程、规则和信息结构，但没有证明照片级人物、真实海岸、动态天气与稳定性能可以同时成立。

因此作出以下路线决定：

1. 现有 Three.js 网页版本保留为设计、规则、交互和快速分享原型。
2. 网页版本停止以“增加剧情天数、扩大地图或堆叠低模内容”作为主要里程碑。
3. 新建独立 Unreal 写实基准项目，验证最终表现与基础交互。
4. Unreal 通过技术阶段门以前，不建设完整岛屿，不制作完整海难场面，不大量购买资产。
5. 最终生产引擎尚未无条件锁定；Unreal 是当前写实路线的首选候选，基准结果决定是否正式采用。

## 三类成果不能混用

| 成果 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 概念图 | 构图、光线、材质气氛和情绪方向 | 隐藏几何、碰撞、动画、交互和实时性能 |
| 网页原型 | 游戏循环、系统规则、信息反馈和路线节奏 | 最终人物质量、真实海岸和大型写实世界性能 |
| Unreal 基准场景 | 写实资产、地形、人物、海水、天气、碰撞和目标设备性能 | 完整游戏已经成立 |

概念图属于“参考资产”，不能作为游戏背景伪装成可交互三维世界。所有玩家需要进入、观察、触摸或改变的区域必须是真实运行的三维场景。

## 场景呈现决策

游戏采用混合呈现，但实时三维世界占主体：

- 玩家观察、移动、判断、采集、涉水和承担风险的部分使用实时 3D；
- 苏醒、风暴来临、发现远方信号等转场优先使用同一场景内的实时电影镜头；
- 远山、云层、海平线和遥远船只可以使用低精度代理、天空或远景资产；
- 只有船体断裂、巨浪冲击等无法在目标设备实时运行且不包含关键选择的镜头，才考虑预渲染视频；
- 预渲染视频不能代替岛屿探索主体。

## 资产生产决策

资产按实际用途选择，不追求把所有参考图自动转换成 3D：

| 内容 | 生产形式 | 第一阶段要求 |
| --- | --- | --- |
| 主角 | 导入的正式骨骼人物 | 比例、骨架、动作、碰撞和授权明确 |
| 海湾地形 | Unreal Landscape 或作者构建的地形 | 地质轮廓、坡度、岸线、碰撞独立可调 |
| 岩石与植被 | 有授权的写实模型与实例变化 | 材质统一、比例正确、具有 LOD 和碰撞策略 |
| 海洋与天气 | 引擎实时系统、材质和 VFX | 可被世界状态驱动，不使用循环视频代替 |
| 道具与残骸 | 导入或定制模型 | 有交互点、碰撞、状态变化和来源记录 |
| 概念画面 | 二维参考 | 只定义视觉语法，不直接进入碰撞世界 |
| 界面与日志 | 二维 UI | 只补充精确信息，不代替环境证据 |

每项运行资产必须记录来源、许可、比例、轴向、中心点、材质、纹理、碰撞、细节层级、骨架或挂点，以及在真实游戏镜头中的性能。

## “驱动”指什么

模型本身不构成游戏。正式实现需要四层驱动：

```text
玩家输入
  移动 / 观察 / 检查 / 拾取 / 使用
        ↓
角色驱动
  控制器 / 碰撞 / 动画状态 / 脚步 / 涉水 / 持物
        ↓
世界运行
  时间 / 天气 / 潮汐 / 资源 / 身体 / 生态 / 事件
        ↓
世界表现
  地形 / 海浪 / 湿润 / 风动 / 光照 / 声音 / 人物反馈
```

表现层读取世界事实，但不自行创造玩法事实。例如天气发布降雨和风，人物、火堆、地面和动物分别计算自己的结果，再以动作、材质、声音和状态变化呈现。

## 本机条件与直接阻塞

2026-08-05 的本机只读检查结果：

| 项目 | 当前情况 | 评估 |
| --- | --- | --- |
| CPU | Intel i9-13980HX，24 核 32 线程 | 满足小型写实基准开发 |
| GPU | RTX 4070 Laptop，8 GB 显存 | 满足 1080p 小型 UE5 基准，不代表全岛 4K 能力 |
| 内存 | 15.6 GB | 低于 Epic 推荐的 32 GB，属于效率与稳定性风险 |
| C 盘空间 | 剩余约 15.1 GB | 当前直接阻塞 |
| F 盘空间 | 剩余约 19 GB | 当前直接阻塞 |

开始 Unreal 项目前应当：

1. 为编辑器、工程、缓存和构建预留至少约 150 GB 的连续 SSD 空间；
2. 长期开发建议规划 300 GB 以上；
3. 内存建议提升到 32 GB，大区域生产再评估 64 GB；
4. 当前 CPU 和 GPU 暂不更换。

## 技术阻塞分级

| 内容 | 当前判断 | 处理方式 |
| --- | --- | --- |
| Unreal 安装与项目空间 | 已阻塞 | 先解决磁盘空间，不绕过 |
| 基础地形、天空和光照 | 无根本阻塞 | 在基准场景中建立 |
| 第三人称人物和基础移动 | 无根本阻塞 | 使用正式骨骼人物验证 |
| 内存不足 | 可运行但风险高 | 32 GB 作为推荐升级 |
| 真实近岸浪、泡沫和湿沙 | 高难点 | 只验证一个海湾，不承诺全岛 |
| 人物涉水、持物、受伤和湿润 | 高难点 | 每次只接入一个动作链 |
| 植被密度与动态天气性能 | 高难点 | 固定最重测试状态并持续测量 |
| 风暴客船断裂 | 暂缓 | 基础世界通过后再决定实时或预渲染 |
| 完整写实岛屿 | 当前阻塞 | 不进入内容生产阶段 |

## 费用边界

第一阶段不存在必须购买引擎或人物工具的费用阻塞：

- Unreal 游戏开发在标准许可门槛内可免费开始；
- MetaHuman 包含在标准 Unreal 许可中；
- 可以使用有明确许可的免费或低成本资产建立基准；
- 不购买不能直接进入基准场景验证的“大而全”资产包；
- 基准通过前，付费资产与插件总预算暂定上限为人民币 3,000 元，任何支出单独记录用途、许可和替代方案；
- 第一笔更可能发生的必要投入是 SSD 空间和内存，而不是引擎授权。

完整游戏的主要成本将来自定制动画、统一美术、动物行为、海难镜头、声音、优化、测试和长期人力，而不是单个软件许可。

## 阶段门

只有以下证据同时出现，才允许把 Unreal 从“候选路线”升级为“正式生产路线”：

1. 一块 50 × 50 米可交互海滩和约 150 × 150 米视觉范围真实运行；
2. 正式人物能够移动、转向、碰撞、涉水、检查和拾取；
3. 海面、浅水、岸浪、泡沫和湿沙在游戏镜头中层次可读；
4. 晴朗能够连续过渡到风暴前沿或暴雨；
5. 1080p 最重状态在参考设备上达到稳定 30 FPS 底线，并记录画质设置和测量方法；
6. 所有外部资产来源和许可可追溯；
7. 结果表明继续扩展主要是内容生产问题，而不是基础方案无法成立。

如果阶段门失败，优先调整画质目标、资产密度、世界范围或目标设备，不通过购买更多资产掩盖问题。
