# Particle Flower Lab

> 状态：**阶段归档**（2026-08-03）。当前版本作为 Research 04 的可运行基线保留，后续优化应另开迭代，不在归档版本上继续无边界打磨。

Research 04：研究如何不用图片、视频或预制 3D 模型，以程序化三维网格和 GPU 粒子生成一束能够绽放、完整旋转与解构的花。

## 研究问题

怎样把“花朵图片叠加到代码画面”升级成真正由代码实时生成、具有正面、侧面和背面结构，并能持续 360° 转动的完整视觉效果？

## 当前实现

- 原生 WebGL 实现，不依赖外部库、模型、图片或网络资源。
- 程序化生成 7 朵雏菊、双层花瓣、花心、花萼、弯曲枝干和 6 片叶子。
- 桌面版主体约 14,090 个三角面，另有约 3,217 个花粉与边缘粒子。
- 透视相机、法线光照和深度测试共同建立正面、侧面与背面层次。
- 开场先完成实体花束绽放，再自动进行 360° 旋转；也可以拖动观察任意角度。
- 支持重新绽放、网格碎片解构、粒子飞散、恢复花束、暂停旋转与速度调整。
- 使用普通脚本而非 ES Module，可以直接打开 `index.html`；本地服务器仍是推荐方式。
- 对窄屏设备降低粒子预算，并支持 `prefers-reduced-motion`。

## 运行

可以直接双击 `index.html`。需要稳定调试或查看控制台时，建议在仓库根目录启动静态文件服务器：

```powershell
python -m http.server 4173
```

然后打开：

```text
http://127.0.0.1:4173/particle-flower-lab/
```

项目没有构建步骤，也不依赖 CDN。

## 文件

- `index.html`：展示结构和控制界面。
- `styles.css`：全屏研究界面及响应式布局。
- `app.js`：三维网格生成、矩阵相机、光照与粒子着色器、动画和交互。
- `IMPLEMENTATION.md`：当前实现原理、架构选择及后续优化路线。
- `ARCHIVE.md`：阶段归档范围、验收结果和重新开启条件。
- `VALIDATION.md`：语法、统一构建、桌面/手机布局和交互验证记录。

## 当前边界

当前版本重点验证“程序化实体网格 + 粒子表层”能否形成可读、可旋转并具有前后结构的花束。它属于可展示的程序化原型，不是照片级植物资产，也没有液体模拟、景深后期或视频导出。后续若追求参考视频的照片级质感，应引入高质量花朵 GLB、透明材质、纹理与后期光晕，而不是继续增加程序化粒子数量。
