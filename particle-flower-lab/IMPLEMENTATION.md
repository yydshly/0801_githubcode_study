# 实现方式与后续优化路线

## 1. 当前版本如何实现

当前版本完全由浏览器运行时生成，不包含花朵图片、视频、外部 3D 模型或 CDN 依赖。

```text
JavaScript 程序化几何
  ├─ 花瓣曲面
  ├─ 花心球面
  ├─ 花萼
  ├─ 曲线枝干
  └─ 叶片曲面
        ↓
三角网格上传 GPU
        ↓
WebGL 网格着色器：绽放、光照、碎片解构
        ↓
WebGL 粒子着色器：花粉、边缘飞溅、解构粒子
        ↓
透视相机、深度测试、360° 旋转和拖动观察
```

### 1.1 花朵主体

主体由约 14,090 个三角面组成：

- `addPetal` 按长度、宽度、弯曲、卷边和角度参数生成双层花瓣曲面。
- `addSphere` 生成花心球面。
- `addSepals` 生成花朵背面的绿色花萼。
- `addTube` 沿二次曲线生成花茎和分枝圆管。
- `addLeaf` 根据叶片宽度曲线、弯曲和拱度生成叶面。
- `addFlower` 将上述结构组合为 7 朵朝向不同方向的雏菊。

不同花朵具有不同的位置、大小和朝向，因此旋转到侧面或背面时仍存在真实结构，不是一张始终朝向镜头的平面图片。

### 1.2 网格渲染

网格使用独立 WebGL 着色器渲染：

- 透视矩阵和观察矩阵建立真实近大远小关系。
- 法线、双向补光、边缘光和高光建立花瓣、花心与叶片层次。
- 深度测试处理前后遮挡。
- `uReveal` 控制花束从根部到花冠依次绽放。
- `uDisintegrate` 让完整三角碎片向外移动并降低透明度。
- 每个三角形共享同一个碎片编号，避免三个顶点分别飞走而产生拉伸尖刺。

### 1.3 粒子层

桌面版约有 3,217 个粒子，手机端约有 2,817 个粒子：

- 花朵周围的白色粒子表现花瓣边缘和空气碎屑。
- 黄色粒子表现花粉。
- 环境粒子增加空间深度。
- 解构时粒子沿各自方向飞散；恢复时重新回到花束周围。
- 粒子采用两次绘制：低透明度大光晕 + 高透明度核心点。

### 1.4 动画与交互

- 页面打开后先完成绽放，随后开始 360° 自动旋转。
- 按住画布拖动可改变水平旋转和俯仰角度。
- 双击恢复英雄镜头。
- 支持重新绽放、粒子解构、恢复花束、暂停旋转和速度调节。
- `prefers-reduced-motion` 开启时跳过自动动画。

### 1.5 为什么不再使用“纯粒子花朵”

第一版让粒子同时承担花朵主体和特效层，结果存在两个根本问题：

1. 粒子轮廓难以稳定表达完整花瓣，第一眼不容易识别为花。
2. 点云缺少连续表面、法线和厚度，完整旋转时会暴露为薄层。

最终采用“实体网格负责花朵，粒子负责特效”的组合。这个结构是本项目最重要的阶段结论。

## 2. 后续可优化的四条路线

| 路线 | 目标 | 优点 | 局限 | 适合场景 |
| --- | --- | --- | --- | --- |
| A. 继续程序化建模 | 保持完全代码生成 | 研究价值高、参数可控、无资产依赖 | 工作量大，照片级真实感上限有限 | 技术实验、生成艺术 |
| B. 高质量 GLB + 实时粒子 | 提升网页实时质量 | 兼顾真实模型、360° 旋转和交互 | 需要模型来源、授权、压缩和加载管理 | **推荐的下一阶段** |
| C. 2.5D 图片分层 | 快速接近参考截图 | 写实度高、开发速度快 | 只能小角度旋转，侧面会暴露平面结构 | 正面短视频、有限镜头 |
| D. Blender 离线渲染 | 达到电影级视频质量 | 可使用高质量模型、流体、景深和运动模糊 | 不是浏览器实时效果，制作和渲染成本高 | 抖音成片、宣传视频 |

### 路线 A：继续优化程序化花朵

建议依次增加：

1. 平滑法线和连续曲面，消除低多边形分面。
2. 花瓣厚度、卷边、褶皱和不规则破损边缘。
3. 花瓣纹理、叶脉、粗糙度与法线细节。
4. 花瓣透光、次表面散射近似和背光颜色。
5. 更复杂的花蕊、花粉和枝干节点。

这条路线适合继续研究“代码能把自然形态生成到什么程度”，但不应承诺快速达到照片级真实感。

### 路线 B：高质量 GLB 模型与实时 WebGL（推荐）

```text
高质量花朵 GLB
→ 模型质量和授权检查
→ PBR 材质、透明度与透光
→ 从模型表面采样粒子
→ 解构、恢复和旋转镜头
→ Bloom、景深和色彩分级
```

这是最适合继续当前网页项目的方向。代码继续负责旋转、镜头、交互和粒子，但花朵真实性由专业模型、纹理和材质保证。

### 路线 C：2.5D 图片分层

将高清透明花朵图片拆成前景花瓣、花心、后层花瓣和粒子层，在空间中错开放置。它能快速接近参考视频的正面质感，但转动范围建议控制在约 ±15°～25°，不适合完整 360° 展示。

### 路线 D：Blender 离线电影渲染

若目标变为“发布一条效果最好的视频”，应使用高质量模型、几何节点、粒子或流体、真实景深、运动模糊与电影灯光，在 Blender 中渲染成视频。网页代码不再承担最终画质，只承担研究或预览功能。

## 3. 推荐的下一阶段顺序

若重新开启项目，建议按以下顺序推进：

1. 获取一份授权清晰、正反面完整的高质量花朵 GLB。
2. 完成模型质量门槛：比例、法线、花瓣厚度、材质、纹理和移动端体积。
3. 将当前旋转、镜头和控制逻辑迁移到模型版本。
4. 从模型表面采样粒子，实现花瓣表面解构，而不是在模型周围随机生成粒子。
5. 增加花瓣透光、Bloom、景深和色彩分级。
6. 最后再研究录制与 MP4 导出。

优先级结论：**先提升花朵资产和材质，再优化粒子；继续单纯增加粒子数量不会显著提升真实感。**
